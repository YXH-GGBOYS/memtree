# EVT-20261103-001 Duplicate invoices when the webhook response was slow

- date: 2026-11-03
- areas: billing
- severity: high
- pitfall: billing/PITFALLS.md#P002 (new, now RESOLVED)

## Symptom

Some customers received two invoices for one payment. Both invoices referenced the same provider event id.

## Root cause

`billing/webhooks.py` created the invoice before recording the event id. When the handler took longer
than the provider's timeout, the provider retried and the second delivery created a second invoice.

## Fix

Record the event id in `webhook_events` (unique index) inside the same transaction, and return 200
early when it already exists. Verified by `tests/billing/test_webhooks.py::test_retry_is_idempotent`
and by replaying one real event twice against staging.

## What would have caught it earlier

A test that delivers the same webhook twice. Added as above; the rule is now in the CRITICAL_FACTS digest.
