# 设计原则

[English](design-principles.md)

## 1. 上下文就是成本

每次调用都会把整段对话重新发一遍，所以 token 花在长会话上（见 [context-economics_cn.md](context-economics_cn.md)）。
会话保持短，东西只注入一次，返回结果尽量小。先量再优化：`token_report.py` 和 `ctx_usage.py` 从
会话记录里读真实用量。没当场量过，就别报上下文百分比；忙了一阵之后，凭感觉估的数往往偏高。

## 2. 每类事实只有一个权威

| 事实 | 权威位置 |
|---|---|
| 硬不变量 | `.memory/CRITICAL_FACTS.md`（DIGEST 段会被注入） |
| 某一块的已知陷阱 | `.memory/<area>/PITFALLS.md` |
| 事件 | `.memory/events/` 及其 `INDEX.md` |
| 一条工作线的进度 | `.memory/threads/<name>.md` |

其它地方只放指针。两处说法不一致就是 bug，按权威去改那份副本。每一次用自己的话复述都是有损复制，
副本的副本会越走越偏。hook 从 CRITICAL_FACTS.md 实时取摘要、不自己存一份文字，也是这个原因。

## 3. 人写的知识优先于生成的摘要

v1 为每个源文件生成摘要，结果过期了也没人读（见 [legacy/README.md](../legacy/README.md)）。源码
永远是最新的；源码告诉不了智能体的，是事情为什么是现在这样、以前坏过什么、哪些规则绝不能破。
MemTree 存的就是这些，由人写（或在收尾时由智能体写），像代码一样审阅。

## 4. 只注入，不转发

MemTree 的 hook 只往上下文里加文字，别的什么都不做。不拦截、不改写、不转发任何工具调用，不加
PreToolUse 处理，不加工具，不保存工具输出。一个把命令交给自己执行器的工具，也就把命令从人们依赖的
PreToolUse 安全 hook 旁边绕了过去，还可能把命令的返回结果存下来。MemTree 根本不碰工具调用，这一类
问题就不会出现。

两个推论：

- 不该出声时不出声：不在 MemTree 项目里（没有含 `CRITICAL_FACTS.md` 或 `memtree.json` 的
  `.memory/`）时，每个 hook 都什么也不打印、以 0 退出，所以装在用户级别是安全的。
- 坏了要大声说：CRITICAL_FACTS.md 在、但 DIGEST 标记缺了，hook 会打印一行红字，说明硬不变量这次
  没注入。安全事实悄悄消失，比它过期更糟。

## 5. 核对模型实际收到了什么

对 hook、注入和门禁来说，证据是模型收到的字节和真实退出码，用 Claude Code 发的同样的 stdin 去跑
才能量到。脚本自己说「OK」不算证据。通道有上限：hook 输出超过 10,000 字符就会被换成文件路径加约
2,000 字符的预览，所以 MemTree 给每个 hook 定了 9,000 字节的预算，并用超长输入测试这个预算。

## 6. 否定断言要有证据

「X 不存在」「做不到」「得新建」这类话，最容易一路被原样传下去，错的时候方向总是多干活。写之前先跑
`verify_absence.py`：两种独立的检索方法，打印原命令和命中数。零命中也只说明「没找到」。还要说清
能力处在哪个状态：

| 状态 | 含义 |
|---|---|
| 不存在 | 什么都找不到，真的要从头建 |
| 已建未接线 | 代码在，没有调用方 |
| 已接线未打开 | 有调用，但开关或配置是关的 |
| 已在运行 | 在跑；说这句话要有运行时证据（数据行、日志、一次真实运行），读代码看不出来 |

还有一个陷阱：在跑，但结论永远是「判断不出」。它有数据行、有日志、有计数，看着像在运行，可每个结果
都是「说不清」。要看它的输出能不能用，而不只是看有没有输出。

## 7. 先问谁在读它

改共享字段、状态值或常量之前，先列出它的使用方（`who_reads.py`）。要逐行看的是判断条件那一组：
`if`、`where`、`filter`、`==`、`in`。字段里装的东西一变，其中某一处可能就恒真或恒假，而且哪里都不报错。

## 8. 只在对话里说的更正不算更正

下一个会话看不到这段对话。写下来的东西被证明错了，就去它所在的文件里改，把旧说法标为作废，并指向
正确的那条。收尾（`memtree-closeout`）就是例行做这件事的地方。

## 9. 卡片带状态，不带授权

交接卡告诉下一个会话：定了什么、做完了什么、什么还没验证、下一步做什么。它从不写「部署已批准」。
上线、部署、改数据的授权，由人在真正执行的那个会话里重新给。

## 10. 保持小

只用 Python 3.9 标准库。没有常驻进程、没有数据库、没有网络调用、没有后台索引。所有东西都是能读、能
diff、能提交的文件。
